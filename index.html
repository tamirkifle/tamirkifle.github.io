LLM Inference Engine

Llama inference in Rust with no PyTorch, no ONNX and no BLAS. I wrote the kernels by hand, benchmarked them, and rewrote the ones that turned out slower than I expected.

21x INT8 over f32 on the matmul that decoding actually runs
6.03GB Llama-7B weights quantized, down from 24.12 in f32
f32 GEMM at 1024 square, 10 cores
157.9 Gelem/s
Naive scalar version of the same kernel
23.3 Gelem/s

Criterion benchmarks on an M1 Pro. The footprint is read out of the running process, not calculated on paper. These are kernel and memory numbers though. A full 7B generation run is still unfinished, so there is no tokens per second figure here yet.

LedgerKV

A key-value store that runs both sides of the CAP tradeoff over one storage engine: Dynamo-style leaderless quorums, and Raft. A linearizability checker in CI decides which guarantee each path actually gives you, so the difference is a test result rather than a README claim.

69,140ops Driven through a live 5-node cluster at about 250 a second
0failed No operation dropped and no quorum ever came up short
Steady-state p99 latency, p50 was 2 ms
15 ms
Time node2 spent dead mid-run
90 s
Tests passing in CI, linearizability checker included
361

One run, one cluster, scraped from each node's /metrics endpoint. Hinted handoff and read repair are both implemented, but I have not measured how long a recovered replica takes to converge, so there is no number for that here.
