# Portfolio redesign

## Problem and audience
Recruiters need a clear role, experience, and next step within seconds. Engineering readers need accurate project descriptions, inspectable work, and explicit limits. The existing site distributes attention evenly across six projects, oversells placeholder writing, and hides experience.

## Requirements
- Independent review of the original presentation, including desktop and mobile.
- A new visual identity, responsive layout, legible type, and original project diagrams.
- Visible experience, three selected projects with dedicated detail pages, a complete project index, background and contact.
- Preserve factual authorship and scope. No invented results, endorsements, availability, hobbies, or articles.
- Public writing only when complete; preserve drafts privately from navigation.
- Static, accessible pages that work without JavaScript; progressive enhancement only.
- Local branch and commit, no push or publication.

## Success criteria
All public pages pass link and browser smoke checks. No horizontal overflow at 360, 390, 768, or 1440px. Keyboard access, reduced motion, readable contrast, light/dark themes, and mobile navigation verified. Review report, maintenance instructions, and local preview delivered.

## Out of scope
Re-evaluating project merit, modifying project repositories, inventing new professional achievements, deployment.

## Final direction from the user
This is an engineering blog organized around projects, not a site selling employment or services. Use a minimalist index, name-first project entries, short project overviews, and multiple associated articles as available. Preserve the custom illustrations. Remove status dots, role/location eyebrows, promotional calls to action, and homepage employment emphasis. Keep background details on About. This direction supersedes recruiter-first homepage requirements above.
